# 스타 보이저(Star Voyager) — 연료 기반 우주여행 보상 체계 계획서

> 별빛로그(Starlog)의 기존 **미션 완료 → 배지 획득 → 칭호 상승** 구조를 **그대로 유지**한 채,
> 그 위에 "학습 활동 → 연료 획득 → 더 먼 별로 항해" 레이어를 얹는 확장 기획서

- 문서 버전: v1.1 (별빛로그 실제 구조 반영)
- 작성일: 2026-07-27
- 대상 서비스: 별빛로그 — 초등학교 학급 단위 감정·성장 기록 플랫폼
- 기술 스택: Next.js 14 App Router · TypeScript · Supabase(Postgres + Auth + Storage) · Zod

---

## 1. 기획 개요

### 1.1 한 줄 요약

학생 한 명 한 명이 자기 우주선을 타고, 매일의 별빛 활동(오늘 계획 체크·감정 기록·성찰일기·클래스메일)과 미션 배지로 **연료를 모아** 달에서 시작해 프록시마 켄타우리까지 **점점 더 먼 별을 향해 항해**하는 성장 레이어.

### 1.2 왜 "연료 → 별"인가

| 기존 배지 체계의 한계 | 연료 체계가 해결하는 지점 |
|---|---|
| 배지는 이산적(획득/미획득) — 오늘 노력이 눈에 안 보임 | 연료는 연속적 — 오늘의 기록 한 편이 즉시 게이지에 반영 |
| 미션이 없는 날은 보상 동기가 없음 | 매일 하는 루틴 활동 전체가 보상 대상 |
| 목표가 "배지 수집"에 머무름 | "다음 별까지 250 연료"라는 명확한 중기 목표 제공 |
| 성장이 추상적(칭호 이름) | 우주 지도 위 자기 위치라는 공간적 은유로 성장 시각화 |

### 1.3 설계 원칙

1. **비파괴적 확장** — 기존 `students.badge_count`·`student_badges`·`class_title_settings`(칭호) 테이블과 `lib/badges.ts` 로직은 변경하지 않는다. 연료는 별도 테이블로 적립되고, 배지 획득은 연료 지급의 *트리거 중 하나*로만 연결된다.
2. **칭호와 기항지는 별개의 축** — 기존 5단계 칭호(별빛 새싹→탐험가→기록자→마스터→전설)는 **배지 개수** 기반으로 그대로 두고, 기항지(별)는 **연료 누적** 기반의 새로운 축으로 병행한다. 서로 덮어쓰지 않는다. (자세한 이유는 4.5 참조)
3. **매일 보상, 가끔 도약** — 소액 연료는 매일, 배지 보너스는 가끔. 꾸준함이 몰아치기를 이긴다.
4. **후퇴 없음** — 연료는 소모되지 않고 누적만 된다. 며칠 빠져도 뒤로 밀리지 않으므로 이탈 학생이 복귀하기 쉽다.
5. **비교보다 자기 항해** — 기본 화면은 자기 우주선. 랭킹은 선택적 기능이며 교사가 끌 수 있다.
6. **교육적 정합성** — 별 지도의 각 목적지는 실제 천체이며, 도달 시 짧은 과학 정보 카드를 제공한다.

### 1.4 기존 체계와의 관계

```
[별빛 활동] ──┬──> 미션 완료 ──> 배지 획득 ──> 칭호 상승(badge_count 기반)   (기존, 유지)
              │  (checkAndAwardBadge)  │
              │                        └──> 연료 보너스 ─┐
              │                                          ├──> 연료 잔고 ──> 우주선 항해 ──> 별 도달
              └──> 계획/감정/성찰/편지 ──> 연료 획득 ─────┘
```

- 배지 = **순간의 성취 훈장** (기존 역할 유지, `student_badges`)
- 칭호 = **배지 개수 등급** (기존 역할 유지, `class_title_settings` · 학급별 커스텀)
- 연료/별 = **여정의 누적 기록** (신규 레이어, 신규 테이블)

## 2. 세계관 및 컨셉

### 2.1 스토리 프레임

> 지구의 관측소가 신호를 보냅니다.
> "먼 우주 어딘가에 아직 아무도 가보지 못한 별이 있어요. 당신의 배움이 곧 연료입니다.
> 오늘 쓴 한 줄, 오늘 지킨 약속 하나가 우주선을 조금 더 멀리 밀어 보냅니다."

별빛로그의 기존 톤("별처럼 빛나는 나의 기록")과 이어지는 확장 스토리로, 학생 카드에 이미 쓰이는 마스코트(🚀🪐🌙🛸)를 그대로 항해 서사에 얹는다.

### 2.2 핵심 용어

| 용어 | 의미 | UI 표기 |
|---|---|---|
| 연료 (Fuel) | 별빛 활동으로 얻는 누적 포인트 | ⛽ 1,240 |
| 우주선 (Voyager) | 학생 개인의 이동체 | 🚀 |
| 항해 거리 | = 누적 연료. 감소하지 않음 | 1,240 AU |
| 기항지 (Star Port) | 도달 시 해금되는 천체 10곳 | 🪐 |
| 항해일지 (Log) | 연료 획득 내역 타임라인 | 📜 |
| 부스터 (Booster) | 연속 참여 시 획득 배수 | ×1.5 |

### 2.3 시각 톤

- 배경: 별빛로그 랜딩과 동일한 딥 네이비(#0f0c29) → 퍼플(#302b63) 그라데이션 + 별 파티클 (기존 `InteractiveStarfield` 재사용 가능)
- 강조색: 연료 게이지 시안(#4FD1E5), 도달 별 골드(#FFD66B), 기존 프라이머리(#6366f1)와 조화
- 배지·칭호 이미지(`/별빛새싹.png` 등)는 그대로 재사용 (신규 일러스트 부담 최소화)
- 우주선은 SVG 3~5단계 티어로만 신규 제작 (연료 누적에 따라 외형 업그레이드). 칭호 이미지와 별개 리소스.

## 3. 연료 획득 규칙 (핵심 설계)

### 3.1 기본 획득표

활동명은 별빛로그 실제 기능명과 배지 트리거(`lib/badges.ts`의 `BadgeTrigger`)에 맞춘다.

| # | 활동 | 대응 기능 / 트리거 | 기본 연료 | 하루 상한 | 비고 |
|---|---|---|---|---|---|
| 1 | 오늘 계획 전체 체크 | 계획(`plan_checks`) / `plan_complete` | 5 | 1회 | 당일 계획 항목 전체 체크 완료 시 |
| 2 | 감정 기록(마음일기) | 마음피드(`emotion_feeds`) / `emotion_save` | 8 | 1회 | 최소 20자 이상 |
| 3 | 성찰일기 작성 | 평가 성찰(`eval_reflections`) / `reflection_save` | 10 | 1회 | 최소 40자 이상 |
| 4 | 클래스메일 발송 | 클래스메일(`letters`) / `mail_send` | 12 | 2회 | 친구 대상, 스팸 방지 상한 |
| 5 | **배지 획득** | `student_badges` / `checkAndAwardBadge` | **50** | 무제한 | 기존 배지 시스템 연동 보너스 |
| 6 | 주간 개근 보너스 | 서버 배치 | 30 | 주 1회 | 주 5일 중 4일 이상 활동 시 |
| 7 | 교사 재량 연료 | 교사 대시보드 | 1~100 | — | 교사 수동 지급 (특별 활동 보상) |

**하루 최대 획득(교사 재량 제외): 5 + 8 + 10 + 24 = 47 연료** (+배지 보너스)

### 3.2 품질 게이트 (남용 방지)

연료는 "썼다"가 아니라 "제대로 썼다"에 지급합니다. 별빛로그의 각 활동은 이미 `content` 필드를 가지므로 글자 수 검증을 서버에서 적용할 수 있습니다.

| 항목 | 조건 | 미충족 시 |
|---|---|---|
| 최소 글자 수 | 감정 기록 20자 / 성찰일기 40자 | 연료 미지급, "조금만 더 써볼까요?" 안내 |
| 동일 문자 반복 | 같은 글자 5회 이상 연속 시 무효 | 지급 보류 |
| 중복 제출 | 직전 제출과 유사도 90% 이상 | 지급 보류 + 교사 알림 |
| 메일 최소 길이 | 15자 이상 | 미지급 |
| 교사 회수 | 부적절 제출 시 교사가 연료 회수 가능 | 항해일지에 사유 기록 |

### 3.3 연속 참여 부스터

| 연속 활동일 | 배수 | 표시 |
|---|---|---|
| 1~2일 | ×1.0 | — |
| 3~4일 | ×1.2 | 🔥 부스터 가동 |
| 5~9일 | ×1.5 | 🔥🔥 |
| 10일 이상 | ×2.0 | 🔥🔥🔥 최대 추진력 |

- 주말·공휴일은 연속 카운트를 **끊지 않음** (등교일 기준, 서울 시간대 `todayDate()` 기준)
- 1회 결석 시 배수는 한 단계만 하락 (0으로 초기화하지 않음 — 이탈 방지)

### 3.4 밸런스 시뮬레이션 결과

참여율별 300회 몬테카를로 시뮬레이션 (주 5일, 배지 평균 2~3주 1개 기준):

| 참여 수준 | 한 학기(16주) 누적 | 도달 기항지 | 1년(32주) 누적 | 도달 기항지 |
|---|---|---|---|---|
| 낮음 (40%) | 약 853 | 소행성대 (3단계) | 약 1,700 | 토성 (5단계) |
| 보통 (70%) | 약 1,515 | 토성 (5단계) | 약 3,015 | 카이퍼벨트 (8단계) |
| 높음 (95%) | 약 2,032 | 천왕성 (6단계) | 약 4,081 | 프록시마b (10단계, 완주) |

**해석**
- 참여율이 낮은 학생도 한 학기 안에 3개 기항지를 밟는다 → "나는 못 간다"는 좌절 방지
- 성실한 학생만 1년 만에 최종 목적지에 도달한다 → 완주의 희소성 확보
- 초반 3구간을 짧게 설계해 첫 2주 안에 첫 도달 경험을 보장

## 4. 별 지도 설계

### 4.1 기항지 10단계

| 단계 | 기항지 | 누적 연료 | 구간 필요량 | 예상 도달 시점(보통 참여) | 해금 보상 |
|---|---|---|---|---|---|
| 1 | 🌙 달 | 100 | 100 | 1주차 | 우주선 티어2, 달 정보 카드 |
| 2 | 🔴 화성 | 300 | 200 | 3주차 | 화성 배경 테마 |
| 3 | ☄️ 소행성대 | 600 | 300 | 6주차 | 우주선 티어3 |
| 4 | 🟠 목성 | 950 | 350 | 10주차 | 목성 정보 카드, 항해 칭호(옵션) "탐사자" |
| 5 | 🪐 토성 | 1,350 | 400 | 14주차 | 우주선 티어4, 고리 이펙트 |
| 6 | 🔵 천왕성 | 1,800 | 450 | 19주차 | 항해 칭호(옵션) "항해사" |
| 7 | 🔷 해왕성 | 2,300 | 500 | 24주차 | 태양계 완주 인증서(PDF 출력) |
| 8 | 🧊 카이퍼벨트 | 2,850 | 550 | 30주차 | 우주선 티어5 |
| 9 | 🌌 성간 공간 | 3,450 | 600 | — | 보이저 기록 카드 |
| 10 | ⭐ 프록시마 b | 4,000 | 550 | — | 최종 완주 훈장 + 학급 명예의 전당 등재 |

> "항해 칭호(옵션)"는 4.5에서 설명하듯 **기존 칭호 시스템과 분리된 별도 뱃지형 호칭**이거나, 교사가 원할 때만 노출하는 선택 요소다. 기본값은 기존 5단계 칭호를 덮지 않는다.

### 4.2 구간 설계 의도

- **1~3단계 (0~600)**: 빠른 성취. 온보딩 구간. 첫 도달까지 최대 1주.
- **4~7단계 (600~2,300)**: 학기 주력 구간. 구간당 3~5주. "태양계 완주"라는 중간 목표가 학기 말과 맞물림.
- **8~10단계 (2,300~4,000)**: 심화 구간. 1년 이상 성실히 참여한 학생을 위한 장기 목표.

### 4.3 별 도달 연출

1. 게이지가 100% 도달 → 화면 전체 감속 연출 (0.6초)
2. 우주선이 별에 접근하는 애니메이션 (2초, 스킵 가능)
3. 기항지 카드 등장: 천체 이름 / 실제 거리 / 과학 상식 한 줄 / 해금 보상
4. "항해일지에 기록되었습니다" 토스트
5. 교사 대시보드에 알림 (선택적으로 학급 전체 화면에 축하 배너)

### 4.4 접근성·정서 고려

- 애니메이션 축소 옵션 제공 (`prefers-reduced-motion` 대응 — 별빛로그 CSS 규약과 일치)
- 다른 학생과의 거리 비교는 **기본 비활성화**. 교사가 켤 때만 노출
- "뒤처짐"을 나타내는 표현(꼴찌, 미달 등) 금지. 대신 "다음 목표까지 ○○"만 표시
- 장기 미접속 학생 복귀 시 "우주선이 당신을 기다렸어요" 메시지 + 복귀 보너스 20 연료

### 4.5 기존 칭호 시스템과의 충돌 해소 (중요)

별빛로그에는 이미 **학급별로 커스터마이즈 가능한 5단계 칭호**(`class_title_settings`, `getTitleByBadgeCount()`)가 있고, 이는 **배지 개수(`badge_count`)** 기반이다. 우주여행 보상이 여기에 또 다른 "칭호"를 얹으면 두 칭호 축이 충돌한다. 그래서:

- **원칙**: 기항지 도달은 **칭호를 바꾸지 않는다.** 학생의 공식 칭호는 계속 배지 개수 기반(별빛 새싹~전설)으로만 결정된다.
- **기항지 보상은 별도 축**으로 준다 — 우주선 티어 업그레이드, 배경 테마, 기항지 인증 카드/PDF, 명예의 전당 등재 등 **코스메틱·기록물** 위주.
- 굳이 항해 호칭을 쓰고 싶다면, `class_title_settings`를 건드리지 않는 **별도의 "항해 뱃지/호칭"**으로 만들고, 학급 설정에서 노출 여부를 교사가 켜고 끄게 한다. (기존 배지·칭호 설정 UI와 동일한 패턴)

## 5. 화면 구성

별빛로그의 학생 영역은 단일 `/student` 페이지 + 서브 라우트(`/student/badges`) 구조다. 항해 화면도 같은 패턴으로 `/student/voyage` 하위에 둔다. 교사 도구는 별도 페이지가 아니라 **교사 대시보드의 새 탭**으로 붙인다(권한설정·알림설정 탭과 동일한 방식).

### 5.1 화면 목록

| 화면 | 위치 | 핵심 요소 |
|---|---|---|

## 6. 데이터 설계

별빛로그 마이그레이션 규약(소문자 SQL, `public` 스키마, `uuid` PK, `timestamptz`, `on delete cascade`, RLS 활성화 후 서비스 롤 `supabaseAdmin`으로 접근)을 따른다. `students.id`는 **uuid**이며 배지 id는 텍스트 슬러그(`'emotion_first'` 등)이므로, 원장의 `source_id`는 uuid·슬러그를 모두 담도록 **text**로 둔다.

### 6.1 신규 테이블

```sql
-- 학생별 항해 상태 (학생 1명당 1행)
create table if not exists public.voyage_state (
  student_id      uuid primary key references public.students(id) on delete cascade,
  total_fuel      int  not null default 0,   -- 누적 연료 = 항해 거리
  current_star    smallint not null default 0,  -- 마지막 도달 기항지 단계 (0=지구)
  ship_tier       smallint not null default 1,
  streak_days     int  not null default 0,
  last_active_on  date,
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now()
);

-- 연료 획득/회수 원장 (append-only)
create table if not exists public.fuel_ledger (
  id           uuid primary key default gen_random_uuid(),
  student_id   uuid not null references public.students(id) on delete cascade,
  source_type  text not null,           -- plan_check | emotion_feed | reflection
                                         -- | letter | badge | weekly_streak
                                         -- | teacher_grant | teacher_revoke | comeback
  source_id    text,                     -- 원본 레코드 id(uuid) 또는 배지 슬러그
  base_amount  int not null,             -- 배수 적용 전
  multiplier   numeric(3,2) not null default 1.00,
  amount       int not null,             -- 실제 반영량 (음수 = 회수)
  earned_on    date not null,
  note         text,
  created_at   timestamptz not null default now(),
  unique (student_id, source_type, source_id)   -- 중복 지급 차단
);
create index if not exists fuel_ledger_student_date_idx
  on public.fuel_ledger (student_id, earned_on desc);

-- 기항지 도달 기록
create table if not exists public.star_arrivals (
  id          uuid primary key default gen_random_uuid(),
  student_id  uuid not null references public.students(id) on delete cascade,
  star_level  smallint not null,
  arrived_at  timestamptz not null default now(),
  unique (student_id, star_level)
);

-- 기항지 마스터 (시드 데이터)
create table if not exists public.stars (
  level             smallint primary key,
  name              text not null,
  emoji             text,
  fuel_threshold    int not null,
  reward_ship_tier  smallint,
  reward_title      text,          -- 항해 호칭(옵션). 기존 칭호와 무관.
  fact              text           -- 도달 시 보여줄 과학 상식
);

alter table public.voyage_state    enable row level security;
alter table public.fuel_ledger     enable row level security;
alter table public.star_arrivals   enable row level security;
alter table public.stars           enable row level security;
```

> 연료 지급은 외부 엔드포인트가 아니라 **서버 내부 함수 `grantFuel()`**로만 호출한다(학생이 임의로 연료를 요청하지 못하도록). 각 활동 저장 라우트가 저장 성공 후 `grantFuel()`을 부른다.

### 6.4 연료 지급 로직 (의사코드)

```
async function grantFuel(supabaseAdmin, studentId, sourceType, sourceId, baseAmount):
    # Postgres 트랜잭션/행잠금은 supabase-js에서 직접 지원이 제한적이므로,
    # unique 제약(중복 차단)과 재조회 정합성 배치로 경합을 방어한다.

    # 1) 중복 방지 — fuel_ledger의 unique(student_id, source_type, source_id)로 1차 차단
    # 2) 일일 상한 검사
    todayCount = count(fuel_ledger where student_id, source_type, earned_on = today())
    if todayCount >= DAILY_CAP[sourceType]: return CAP_REACHED

    # 3) 부스터 계산
    state = select voyage_state where student_id   # 없으면 default로 upsert
    updateStreak(state)                            # 등교일(서울) 기준 연속일 갱신
    mult = multiplierFor(state.streak_days)        # 1.0 / 1.2 / 1.5 / 2.0
    amount = floor(baseAmount * mult)

    # 4) 원장 기록 (unique 위반이면 이미 지급된 것 → 조용히 종료)
    insert into fuel_ledger(...)  on conflict do nothing → 반영 0건이면 return ALREADY_GRANTED

    # 5) 잔고 반영 + 기항지 도달 판정 (여러 단계 동시 통과 가능)
    newTotal = state.total_fuel + amount
    newStars = stars where fuel_threshold <= newTotal and level > state.current_star
    for star in newStars:
        upsert star_arrivals(studentId, star.level)  # on conflict do nothing
        if star.reward_ship_tier: nextTier = max(nextTier, star.reward_ship_tier)

    update voyage_state set total_fuel=newTotal, current_star=maxLevel, ship_tier=nextTier, ...

    return { amount, multiplier: mult, totalFuel: newTotal, arrivedStars: newStars }
```

### 6.5 배지 시스템 연동 (비침습적)

별빛로그는 이벤트 버스나 DB 트리거가 **없고**, 배지는 각 활동 저장 라우트에서 `checkAndAwardBadge(supabase, studentId, trigger, ...)`(`lib/badges.ts`)를 직접 호출해 지급한다. 따라서 연료도 같은 지점에 얹는다.

- **활동 연료**: 각 활동 저장 API(감정 기록·계획 체크·성찰·클래스메일)에서 `checkAndAwardBadge` 호출 직후 `grantFuel(...)`을 함께 호출.
- **배지 보너스 연료**: `checkAndAwardBadge`가 반환하는 "이번에 새로 획득한 배지 목록"을 순회하며 배지 1개당 `grantFuel(studentId, 'badge', badgeId, 50)`.
- 두 호출 모두 **best-effort** — 실패해도 원래 활동/배지 저장은 성공해야 하므로 try/catch로 감싸고 실패 시 로그만 남긴다. 누락분은 야간 정합성 배치(6.6)에서 보정.

### 6.6 정합성 배치

야간 배치(또는 관리자 수동 실행)로 `fuel_ledger` 합계와 `voyage_state.total_fuel`을 대조하고, 활동 테이블 대비 미지급분(훅 실패로 누락된 연료)을 소급 지급한다. 배지 소급은 `student_badges` 대비 `fuel_ledger`의 `source_type='badge'` 누락분을 채운다.
